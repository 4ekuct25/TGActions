# Правила работы над TGActions

Единственный файл с правилами для агентов; `CLAUDE.md` — ссылка на него.
Что делает модуль и как устроен код — в `README.md`, здесь только то, что должно
срабатывать **в момент работы**, а не вспоминаться после ошибки.

## Адрес хаба

Работать через **локальный адрес хаба** в домашней сети — `http://<ip-хаба>/`.
Сам адрес спросить у владельца: в репозитории его нет, репозиторий публичный.
Облачный `web.spruthub.ru` открывается и показывает закешированные версии, но живые
данные может не отдавать вовсе: висит «Подключение к серверу», списки сценариев и
устройств пустые. Выглядит как пустой хаб, а на самом деле это отсутствие связи —
не делать из такой картины никаких выводов о содержимом хаба.

## Выкладка в хаб — по шагам, без пропусков

Каждый шаг здесь оплачен сломанной выкладкой. Подробности инцидентов — в `JOURNAL.md`.

1. **Гейты до сборки.**
   ```bash
   python3 tools/scenarios.py check      # экспорты соответствуют src/
   node tools/settings-harness.js        # exit 1, если политика доступа поехала
   ```

2. **Собрать версию с секретами.**
   ```bash
   python3 tools/scenarios.py build --local
   ```
   Кладёт в `dist/` (вне git). **Записать числа строк из вывода** — они понадобятся
   на шаге 4. Импортировать в хаб только из `dist/`: в корне лежит сборка с
   плейсхолдерами.

3. **Импортировать.** В хабе: Сценарии → «+» → «Импортировать шаблон» → файл из
   `dist/`. Прежний одноимённый сценарий **удалить до импорта**, иначе в хабе
   окажутся два и движок подхватит непредсказуемый.

4. **Сверить число строк — обязательно.** Хаб молча не сохраняет крупные сценарии и
   при этом гасит значок «сохранить», как будто всё удалось. Рабочий потолок ~47 КБ,
   61 КБ не доезжает точно. Проверять так: перезагрузить страницу редактора, кликнуть
   в текст, `Cmd+↓`, сверить номер последней строки с числом из шага 2. Не сошлось —
   сценарий залит частично, и никакие дальнейшие проверки смысла не имеют.

5. **Перезагрузить хаб.** Настройки → Информация → Перезагрузить → Продолжить.
   Это **единственный** способ перезапустить глобальный сценарий (см. «Чего не делать»).

6. **Дождаться автостарта.** Опрос поднимает блочный сценарий `Part 3. Auto start bot`
   примерно через 200 секунд после старта хаба. Раньше этого срока пустой журнал
   ничего не значит — ждать, а не чинить.

7. **Проверить журнал хаба.** Сценарии → «•••» → «Отладка», поиск `TGActions`.
   Ожидается: `Registered N commands for <бот>`, затем `pollOnce` примерно каждые
   9 секунд, по одному `scheduleNextPoll` на каждый. Признаки беды: конфликты 409,
   две строки `pollOnce` на одну секунду (несколько циклов опроса), тишина.

8. **Проверить в чате.** `/home` → комната → устройство → нажать действие. «Сервис
   поднялся» — не проверка; проверка — сработавшее устройство.

## Чего не делать

- **Не нажимать «Тест» (▷) на глобальном сценарии.** Он исполняет код и поднимает
  новый экземпляр движка; метка поколения гасит живой цикл опроса, а своего цикла
  «Тест» не оставляет — бот замолкает наглухо. Пересохранение сценария тоже не
  помогает: текст не изменился, хаб считает его чистым.
- **Не читать характеристику сразу после записи** — значение доезжает асинхронно,
  немедленное чтение возвращает старое. Бот подтверждает намерение, а не результат.
- **Не править собранные `*.json` руками** — `build` перезапишет. Источник правды `src/`.
- **Не запускать `extract` для сценариев с `layout: modules`** — хаб отдаёт движок
  одним куском, обратно по модулям он не раскладывается.
- **Не коммитить `dist/` и `src/02-settings/local.js`** — там реальный токен, а
  репозиторий публичный. Оба в `.gitignore`; перед коммитом и перед push диффы
  проверять на секреты (`git diff --cached` и `git diff origin/main...HEAD`).

## Среда

Сценарии исполняет Nashorn: **только ES5**. Ни классов, ни модулей, ни промисов,
ни spread, ни `Object.assign`.

Глобальному сценарию запрещено менять характеристики и ставить таймеры, и отказ
**молчаливый** — исключения нет, `try/catch` его не видит, след остаётся только в
журнале хаба. Работает лишь когда вызов пришёл по цепочке от блочного сценария,
то есть от `Part 3. Auto start bot`. Поэтому автозапуск обязателен, а не желателен.

## Гейты перед коммитом

`check` повешен на pre-commit, но хук локальный для клона — в новом клоне включить:

```bash
git config core.hooksPath tools/hooks
```

Полный набор:

```bash
python3 tools/scenarios.py check
node tools/settings-harness.js
node tools/engine-harness.js <собранный-скрипт>   # A/B: трасса не должна меняться
python3 tools/mutation-check.py                   # у стендов должны быть зубы
```
